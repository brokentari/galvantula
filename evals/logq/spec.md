# logq

Build a Go command-line tool named `logq`, with its main package at `./cmd/logq`, that filters and summarizes log lines. Build it as four packages: the line parser in `./internal/parse`, the filter expressions in `./internal/filter`, the output formats in `./internal/render`, and the command in `./cmd/logq`, which wires them together. It reads log lines from the files named as arguments, or from standard input when there are none. A log line looks like `2024-03-05T10:15:30Z ERROR auth user=ana action=login ms=120 msg="bad password"`: a UTC timestamp, a level (`DEBUG`, `INFO`, `WARN` or `ERROR`), a component name, then any number of `key=value` fields, where a value with spaces is in double quotes and a quote inside it is escaped with a backslash. A line that does not fit this form is counted as bad and skipped. The `--level` flag keeps lines at that level or above (`DEBUG` < `INFO` < `WARN` < `ERROR`). The `--component` flag keeps lines from one component. The `--where key=value` flag keeps lines whose field has exactly that value, and may be repeated; a line must meet every condition. The `--since` and `--until` flags take timestamps in the same format and keep lines at or after, or before, that time. The `--format` flag is `text` (the default, which prints each kept line as it was read), `json` (one JSON object per kept line, with the keys `time`, `level`, `component` and `fields`, which holds the fields as strings), or `count` (prints only the number of kept lines, then a space and the word `lines`, such as `3 lines`). After the output, print a note to standard error, `skipped N bad lines`, if any lines were bad. If a file cannot be read, print an error that names the file to standard error and exit with status 1. A bad flag value, such as an unknown level or format, or a timestamp that does not parse, exits with status 2. With no kept lines, print nothing in `text` and `json` formats and exit with status 0.
